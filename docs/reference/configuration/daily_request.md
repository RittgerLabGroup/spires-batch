# Batch-request field guide

[Reference index](README.md) · [CLI guide](../cli.md)

This is field documentation, not a runnable configuration. Field names are
shown exactly as used in configurations. Dotted headings show nested fields;
the section name identifies the interface, not an extra JSON wrapper.

Generated by `scripts/build_config_reference.py`; see the index for maintenance.

Configuration reference for the baseline batch_request interface used by R0 and advanced batch stages. Copy examples/r0.json for R0 or examples/historical.json for the full matched historical pipeline. The authoritative batch-request schema is produced by spires-batch schema request.

Configuration schema version: **1**.

## Cross field rules

- Unknown fields are rejected everywhere in a runnable request.
- Relative paths resolve relative to the request file.
- steps must be unique and ordered build_r0, invert, albedo, interpolate.
- The batch-request interface does not execute interpolation; use the dedicated interpolation interface or a unified workflow job.
- build_r0 requires r0.mode=build, a sensor-appropriate recipe, and r0_source inputs.
- invert requires reflectance inputs, an r0 section, and a LUT named inversion_lut.
- standalone albedo requires raw inputs.
- Selected albedo operations require their named LUT and ancillary inputs.
- A tiled static context root advertises supported ancillary and static-mask names during schema validation; discovery and preflight verify actual per-tile cardinality.
- update_atomically is supported only for standalone albedo on an existing raw product.
- A custom execution profile must supply both resources.cluster and resources.partition.
- Explicit tile routing requires profiles, tile_profiles, and coordinator_profile; tile_profiles must exactly cover selection.tiles.
- All routed profiles in one operational request must use the same Slurm cluster and environment.
- Legacy profile, max_concurrent_tasks, and resources fields cannot be combined with explicit tile routing.
- Staging root is required when staging is enabled.
- Input filename identities must agree with explicitly declared tile, date, water_year, and product.
- R0 start_date and end_date must be supplied together.
- For a complete water year, dates=[] means all discovered files in the selected water year; it does not assert that every calendar date exists.
- R0 build date bounds default from recipe and artifact.water_year; otherwise both bounds are required. Only available sources within the resolved window and optional selection.dates are selected. Preflight reports source-file count, date coverage, and missing requested dates; gaps warn, while no selected sources is an error.
