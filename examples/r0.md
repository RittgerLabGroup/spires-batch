# Build reusable R0

Use [r0.json](r0.json) to build R0 separately for the five-tile example.
Skip this task if suitable validated R0 files already exist; bind those files
explicitly in downstream requests.

## 1. Set the processing WY and destinations

For each `r0.artifacts` entry, set `tile`, processing `water_year`, and
`path`. The example WY2026 output includes `viirs_h08v05_r0_2025.nc`:
2025 describes the source summer, not the processing WY.

The `viirs_summer_composite` recipe derives June 1–September 30 of WY minus one.
No daily date list is required. An explicit pair of artifact start/end dates
overrides the recipe window; `selection.dates` can further restrict selection.
Reflectance must already be downloaded. Check the source root and pattern.

Copy `scheduler_policy.json` beside the request. Set output/staging roots and the
`execution.resources.science_python` to your installed `spipy14/bin/python`.
The worker and its coordinator use that absolute interpreter. R0 loads all summer scenes for one tile/year into
RAM before selection. The example reserves an exclusive full-memory blanca-snow
node and builds one tile at a time.

## 2. Plan and review

```bash
spires-batch validate r0.json
spires-batch plan r0.json --output r0-plan.json
spires-batch dry-run r0-plan.json
spires-batch stage r0-plan.json
```

These commands do not submit jobs. The last command previews staging; it does
not copy without `--execute`. Inspect the source-date coverage, missing dates,
destinations, planned transfer size and resources before proceeding.

## 3. Submit and monitor

Use fresh launch/state destinations for a new run:

```bash
module try-load slurm/blanca
spires-batch submission start-operational r0-plan.json --state-root r0-state --output-dir r0-launch
```

This submits managed work and handles its stage order and capped retries.
Follow the returned run record, job IDs and logs; use
`submission summarize-operational OPERATION_RECORD` to refresh its summary.
Do not run R0 directly on a login node.

## 4. Verify and bind

Confirm successful scientific output validation, the tile/grid, and source
summer. Keep the plan and receipts. Bind each exact new R0 path, including its
coordinate datasets, in historical and NRT requests; the examples already agree
on those paths. Archive reusable outputs explicitly before deleting scratch.
